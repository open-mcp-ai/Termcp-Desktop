# SSH 工作台设计

产品定位是以 termcp 为统一后端的 SSH 管理工具，并保留 Core 管理与 WebUI 的资源操作入口。GUI 不维护第二套 SSH 客户端。

## 资源与视图

| 对象 | 所属层 | 含义 |
| --- | --- | --- |
| 连接配置 | Core | 可复用的 SSH 参数与跳板引用 |
| Session | Core | 一条已建立的 SSH 或本机连接 |
| Shell | Core | 在 Session 上创建的独立终端进程 |
| 工作区标签 | GUI | 一组终端视图，可跨主机、跨 Session |
| 窗格 | GUI | 引用一个 Session / Shell，不拥有连接生命周期 |
| 分组、收藏 | GUI | 连接配置的导航元数据 |
| 分屏布局树 | GUI | 窗格、左右/上下切分方向及切分比例 |

点击主机“连接”会通过 Core 创建新 Session 与首个 Shell；分屏默认在焦点 Session 上新建 Shell，复用同一连接。“添加终端”可打开已存在的 Shell，或连接另一台主机。重新打开没有 Shell 的活跃会话会创建首个 Shell，不新增连接。

## 布局与输入

左右、上下分屏支持嵌套，分隔线可拖动，也可使用方向键调整比例。平铺是临时展示模式，保留原分屏树；最大化和收起都可恢复。原型单工作区限制为 8 个窗格。

每个窗格标明主机和 Shell。输入开关与回显按窗格独立，默认不广播命令。焦点窗格决定右侧详情、文件、转发和通知的归属。GUI 输入与 MCP 输入仍然共享，不意味着独占控制。

正式版布局变化需要对每个可见 Shell 发送其实际字符尺寸。原型只有文本回显，不包含终端模拟器、键盘转义、鼠标协议、滚动历史或真实 resize。

## 关闭行为

- 移除窗格、关闭工作区、收起终端：关闭或隐藏视图，Shell 和 SSH 连接继续运行。
- 关闭 Shell：明确关闭 Core Shell 资源，移除引用它的窗格；Session 仍可新建 Shell。
- Shell 自然退出：窗格保留只读输出。
- 结束 Session：关闭该会话的 Shell 与转发，移除对应窗格并保留历史。
- Core 停止/重启：所有活跃会话断开、归档，工作区不自动创建替代连接。

## 主机详情

参考 [XTerminal 监控侧栏](https://docs.xterminal.cn/getting-started/interface-overview/)和 [HexHub 状态工具条](https://www.hexhub.cn/imgs/ssh1.png)，采用暗色紧凑面板：连接身份 → 监控 / termcp 标签 → 对应内容 → 数据来源。

监控包含系统、运行时间、CPU 趋势及核心使用率、内存、网络、磁盘。termcp 标签包含连接参数、Core 来源、Shell 列表与会话/Shell 资源 URL。资源 URL 的 Shell 数字按 Core 返回的 Shell 列表索引生成。

当前 Core 没有监控 API。正式版需通过独立采集通道提供主机级快照，不污染用户 Shell 输出，并区分未采集、权限不足、连接中断、过期数据。默认示例主机使用静态快照，新配置显示未采集。

## 当前范围

所有操作只改变演示数据，不建立 SSH 连接、不执行命令、不调用 Core。主机跳板配置检查循环引用；凭据不保存。工作区、分组、收藏及布局均在页面内存中，刷新会重置；正式版需按 Core 实例保存，并在加载时校验 Session 与 Shell 是否仍存在。
